- **`plaid_item_ref`** (property, `openapi/schemas/ep4-payments.yaml`
  `ExternalAccountLink.plaid_item_ref`, also referenced by description in
  `openapi/schemas/webhooks.yaml`'s `AccountLinkWebhook.item_id`). The
  canonical table in `.softhouse/code-sync-brief.md` maps this to
  `account_link_ref` but classifies it as a "column" (ORM) rename, and this
  run's explicit instruction list did not include it (unlike
  `persona_inquiry_id`, which was explicitly called out as a schema
  property). Renaming the *key* here would touch a field also present in the
  ORM/migration DDL gate, which is a **different agent's** disjoint scope
  (`app/models/*.py` + `migrations/versions/0001_initial.py`, gate-coupled
  per `app/db/check_migration.py`) — renaming only the OpenAPI side would
  desync the two, and the OpenAPI validator has no visibility into that
  coupling to catch it. I left the field name as-is and only neutralized the
  vendor language in its description, adding an explicit inline note that the
  key itself is pending a follow-up rename to `account_link_ref` to match the
  ORM side. **Flagging for the orchestrator**: confirm whether the
  ORM-renaming agent for T2's sibling task also renames the OpenAPI property,
  or whether a follow-up task should close this gap.
- Payment-rail enum values (`ACH`/`WIRE`/`RTP`/`INTERNAL_P2P`, `EXTERNAL_ACH_IN`
  etc.) — explicitly out of scope for this task; still marked "PENDING
