## (1) Alembic autogenerate CI check — backlog #5

Added a new step to the `backend` job, **after** `Apply migration to Postgres` and
**before** `Tests`, named:

> `Autogenerate diff is empty (models == applied migration on real Postgres)`

**What it asserts.** Against the SAME real `postgres:16` service the previous step
just ran `alembic upgrade head` on, it runs Alembic's autogenerate *programmatically*
and asserts it would emit **zero** operations — i.e. `Base.metadata` (the ORM models)
and the applied migration agree on a full DB round-trip.

**How it asserts empty (mechanism).**
- `_load_all_models()` populates `Base.metadata` (the same loader used by the ORM
  and offline-migration gates, so the model set is identical).
- Opens a real connection with `create_engine(DATABASE_URL)` and
  `MigrationContext.configure(conn, opts={"compare_type": True,
  "compare_server_default": True})` — stricter than the offline check: it compares
  column TYPES and SERVER DEFAULTS as the live database actually reflects them.
- `produce_migrations(ctx, Base.metadata)` runs autogenerate **into an in-memory
  `MigrationScript`** (no file written). Its `.upgrade_ops` is inspected with
  `upgrade_ops.is_empty()`.
- Empty → print PASS, `sys.exit(0)`. Non-empty → print FAIL, print the detected
  operations via `render_python_code(upgrade_ops)` (best-effort; falls back to
  iterating `upgrade_ops.ops`), then `sys.exit(1)` — a nonzero exit fails the job.

**Why it's stronger than the existing gates.** `check_migration` is an *offline*
DDL-string comparison (mock engine, no socket). It cannot see anything that only
manifests after DDL is applied to a real Postgres — e.g. a server default the DB
normalizes, or a type the dialect reflects differently. This step catches that class
of drift on a real round-trip. It does **not** weaken or replace any existing step;
`check_models`, `check_migration`, the upgrade, and `pytest` are all untouched.

**Why it lives only in CI.** It needs a live Postgres, which only exists as the CI
service; it reuses the existing `DATABASE_URL:
postgresql+psycopg://dcb:dcb@localhost:5432/dcb`.

**Local verification done** (no Postgres available here, so the step itself could not
be executed): alembic 1.16.5 confirmed to expose all APIs used
(`MigrationContext.configure`, `produce_migrations`, `render_python_code`,
`UpgradeOps.is_empty`); the embedded Python `py_compile`s clean; the YAML parses
(`yaml.safe_load`) and lists the new step in the correct position.

## (2) verify-docs.sh meta-doc exclusion — backlog #10

**Problem.** The gate greps ALL `final_requirements/*.md`. `07_ledger_audit_verdict.md`
is a META/AUDIT doc that legitimately QUOTES the defects it found in `06` — the
pre-migration USD par, US vendor/rail-named clearing accounts, and float/DECIMAL — to
REPORT them, not to prescribe them. Scanning it flags an audit for accurately
describing the thing it audits.

**Fix — explicit filename allowlist of meta docs, excluded from ALL counters.**
```
META_DOCS=(07_ledger_audit_verdict.md)
```
A `FILES=(...)` array is built ONCE at the top: every `*.md` except files whose
`basename` exactly equals an entry in `META_DOCS`. Every counter — the `c()` helper,
the DRIFT counts (usd/rails/vendor) and every prose HARD count (FDIC/NCUA,
first_name/last_name, float/DECIMAL, UTC+8, MNT-3m threshold) — now scans
`"${FILES[@]}"` instead of `"$DOCS"/*.md`.

**Why filename-only is non-abusable.** The exclusion is by **explicit basename match
only** — never by pattern, proximity, or any "this hit is only a quote / not near a
real violation" heuristic (that kind of context exclusion is the loophole this
deliberately avoids). Consequences:
- A normal spec doc (01–06) **cannot opt itself out** by how it phrases a line. No
  wording change to a spec can dodge a check.
- The ONLY way a file escapes the checks is to be **named, in this reviewed list, in a
  diff a human reads**. The list is short, commented, and reviewable.
- 01–06 remain FULLY checked, exactly as before.

**Baseline consistency.** `--baseline` writes usd/rails/vendor from the SAME `FILES`
set, so the baseline is computed over the identical non-meta set it is later measured
against. A meta-doc hit can never inflate a baseline nor be measured against one.

## (3) 07 restoration — precise controller wording

Because 07 is now excluded, its earlier gate-driven euphemisms were reverted to the
exact literals a controller needs (substance identical; only the descriptions made
precise again):
- USD par: `USD 25.00` / `USD 25` → **`$25.00`** (3 occurrences).
- Clearing accounts: ``1010`/`1040`/`1050` (…named clearing)`` →
  **`1010 Stripe Clearing`, `1040 Wire Clearing`, `1050 RTP/FedNow Clearing`** (the
  real names as they appear in `06`), in both §2 and the open-items list.
- Precision: `no floating-point` / `no-floating-point` → explicit **`float`** and
  **`DECIMAL`** type words (the non-negotiable's own terms).

07 now contains hits that WOULD trip the gate if scanned (3×`$25.00`, 2×`DECIMAL`,
2×`float`, 2×`Stripe`, 2×`Wire Clearing`, 2×`RTP/FedNow`) — proving the exclusion is
load-bearing — yet the gate still PASSES with unchanged counts.
