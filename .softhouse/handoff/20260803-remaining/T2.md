## Problem (from `07` §3)

`06` §6.4 Step 3 prose already says the four DEC-10 patronage factors aggregate by two
different rules — VOLUME factors (`avg_savings_balance`, `transaction_volume`) by **SUM**,
RATE factors (`loan_repayment_performance`, `governance_participation`) by a
**membership-month-weighted average** — but the **pseudocode used a single uniform
`aggregate`**, so an implementer coding to the formula reintroduces the Draft-1 category
error. Money-material: `07`'s worked stakes are a **~180,000,000₮/member swing** (one
governance factor, two equally-perfect members 12-month vs 3-month → weighted 50/50 vs
sum 80/20 on a 600,000,000₮ pool).

## Step-3 encoding — before / after

**Before** (single uniform aggregate for all four factors):
```
for each factor k ∈ {avg_savings_balance, transaction_volume,
                     loan_repayment_performance, governance_participation}:
    F_k(m) = the member's fiscal-year aggregate of monthly E-31 values for factor k
    S_k    = Σ_over_eligible_members F_k(m)
```
(prose below the block said aggregation "differs by factor type" but nothing encoded it.)

**After** (kind is explicit; implementer must not fold back into one loop):
```
factor_kind(avg_savings_balance)          = VOLUME
factor_kind(transaction_volume)           = VOLUME
factor_kind(loan_repayment_performance)   = RATE
factor_kind(governance_participation)     = RATE

J(m)  = fiscal-year months for which m has a contributing E-31 row   // see LA-11
mm(m) = |J(m)|                        // membership-months — RATE weight (integer)

if factor_kind(k) = VOLUME:                      // SUM
    F_k(m) = Σ_{j ∈ J(m)}  v_k(m, j)             // monthly minor-unit balance or count (integer)

if factor_kind(k) = RATE:                        // membership-month-weighted AVERAGE
    RATE_SCALE = 10⁴                             // Decimal(5,4) → integer s_k ∈ [0,10⁴]; no float, no DECIMAL type
    if mm(m) = 0:  exclude m from factor k        // LA-11 absent-value — NOT scored 0
    else: F_k(m) = ⌊ ( Σ_{j ∈ J(m)} s_k(m, j) ) × RATE_SCALE / mm(m) ⌋   // mean at fixed scale 10⁸ (integer)

S_k = Σ_over_eligible_members  F_k(m)            // same kind & scale within k
```
Integer discipline stated and consistent with §5.2: RATE mean uses scaled integers
(`RATE_SCALE = 10⁴`, result at scale 10⁸, one bounded integer division per member); each
factor's internal scale (1 VOLUME / 10⁸ RATE) cancels against its own `S_k`, feeding the
**unchanged** `SCALE = 10¹²` int128 apportionment (Steps 4–6). The `F_k/S_k` share is still
never computed as an isolated division — Step 4 folds it. The RATE per-member truncation is
a weighting quantity, not money; L-7 (Σ entitlement = pool) still holds by construction.

The `S_k = 0` factor-drop rule and the degenerate `every S_k = 0 → abort` case are preserved.
The "why the two kinds differ" rationale (perfect-3-month vs 12-month) is preserved, now
backed by the pseudocode. Step heading renamed "Factor sums" → "Factor aggregation"; the
**"Step 3" label is unchanged** (LA-11, `07` §3 both cite §6.4 Step 3).
